# 知识库入库与维护

本说明对应 v2.0.0 的 `knowledge.html` 与 `V066__knowledge_ingestion.sql`。已有部署需先核对迁移状态，再启用新版；升级顺序见 [v2 升级指南](V2_UPGRADE.md)。

## 数据与可见性

- `ai_rag_ingestion_task` 保存任务归属、阶段、进度、尝试次数、错误摘要和工作租约；账号身份取自登录会话。
- 原件保存在应用私有数据目录，默认 `./data/rag-ingestion`。路径只使用生成的 UUID，不使用上传文件名；接口不会返回原件路径、校验值或工作租约。
- 文件内容以 SHA-256 去重，范围是“用户 + 知识库标签”；同一用户同一标签下的重试使用稳定文件与片段标识。
- 全部索引完成后登记文件目录，再将任务标记为成功。统一召回门读取 MySQL 发布状态；处理中、失败、取消和删除中的任务片段不会进入向量或关键词检索结果。
- 原有不含任务记录的资料按其已启用目录、用户、标签和文件来源继续可用。新片段还必须匹配完整文件标识。发布元数据不可用时检索失败，不跳过检查。
- 这不是跨 PostgreSQL、Elasticsearch 和 MySQL 的分布式事务：存储中可能暂时存在不可见的部分写入。显式重试会先清理失败范围，删除失败会保留任务或目录供再次清理。

## 使用流程

1. 打开“我的知识库”，选择标签和文件。`202 Accepted` 表示原件已保存并排队，不等于已入库。
2. 页面每 5 秒刷新活动任务，展示校验、解析、上下文生成、向量写入、关键词写入和目录发布阶段。
3. 失败保留原件并展示可供用户理解的原因。“重试入库”先校验原件，再清理上次的部分写入，随后重新执行；会再次产生相应模型用量。
4. “查看片段”按文件归属读取已存储文本，每页最多 10 段、每段最多 6000 字，不调用模型。处理中预览可能显示尚未发布的本人片段。
5. “检索测试”仅查询本人的已启用知识库，展示两条检索分支的状态和召回片段。它使用向量模型，不生成聊天回答。
6. 删除活动任务先请求取消。工作线程实际退出后，页面显示等待清理，再点击删除清理索引、目录和原件。不会对仍在写入的任务并发清理。

旧聊天上传接口仍等待入库真正完成后才返回成功；等待超时会提示到知识库页面查看任务，不把排队当成成功。

## 配置与部署前检查

```yaml
agent:
  rag:
    ingestion-dir: /app/data/rag-ingestion
    max-upload-bytes: 20971520
    vector-table: vector_store
    retrieval-timeout-ms: 5000
    retrieval-workers: 4
    retrieval-queue-capacity: 64
```

- 向量表名按 `agent.rag.vector-table` → `spring.ai.vectorstore.pgvector.table-name` → `vector_store` 的顺序解析，兼容原 Spring AI 默认表。入库、检索、预览和删除使用同一表名；必须指向现有 RAG 向量表，不能仅根据默认值创建新表。原本显式使用 `vector_store_openai` 的环境仍应保留该表名配置。
- 原件目录需放在可持久化的私有应用数据卷，不能配置到静态网页目录。备份时同时包含 MySQL 元数据、该目录和原有向量/关键词数据。
- 先执行 V066，再启动含本功能的应用；迁移缺失时入库队列记录错误并停止接收成功结果，检索发布门也会拒绝未验证的数据。
- 当前任务工作池每个应用进程只有 1 个工作线程，队列由数据库持久化。面向现有单应用部署验证；多副本需共享原件卷并验证租约、网络分区与存储写入的隔离后再启用。
- 当前限制单文件大小，尚无每用户累计存储量、文件数或排队任务数配额。开放上传前应监控私有数据卷容量，并根据部署规模限制入口流量。
- 进程异常退出后，过期任务转为失败，原件保留；不会自动再次消费模型额度。用户确认后重试或删除。
- 平台向量/辅助模型授权由个人模型策略与实际模型 HTTP 请求共同校验。关闭授权后不静默改用别人的密钥。

## 离线验证入口

- `RagIngestionLifecycleTest`：执行 V066 的 H2 任务状态、归属、去重、重试清理、取消/删除顺序、源文件安全及发布可见性。
- `KnowledgeAccessTest`：知识库接口鉴权、owner 过滤、辅助模型策略、检索降级/失败和预览范围。
- `RagStorageContractTest`：ES bulk 单项失败、删除响应完整性、旧文件名精确匹配、关键词发布门。
- `src/test/frontend/knowledge-ui.integration.cjs`：本地静态页面 + mock API；上传排队、任务操作、分页、CSRF、文本转义、降级提示和移动布局。

上述测试不请求真实模型，也不读写生产服务器或原数据库。
