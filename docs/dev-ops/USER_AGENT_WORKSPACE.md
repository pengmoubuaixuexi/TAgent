# 个人 Agent 工作区

## 用户入口

登录后从首页进入 **我的 Agent**（`/user-agents.html`）。

- V063 将归属管理员、已启用、未归档且不是副本的原始 Agent 发布到公共库。新用户注册并登录、旧用户刷新登录态时，自动分配本人的运行副本；保留用户主动归档的状态。分配只写数据库，不会在登录时连接外部 MCP。公共副本不占个人自建 Agent 的 30 个配额。
- 创建个人 Agent：先选择执行模式，在左侧节点图选择节点，右侧分别配置模型、Prompt、MCP 连接及 Advisor；具体工具在运行时按需加载。Fixed 支持 1–8 个顺序节点，Auto 保留分析/执行/质检/总结四阶段，Flow 保留能力分析/规划/执行三个角色，具体任务 DAG 在运行时生成。
- **AI 辅助搭建**位于编辑器内，调用所选平台模型为每个节点生成独立指令。生成结果先预览，点击“应用到画布”后可修改，最后由用户保存。不再创建独立的搭建助手对话；以前的助手数据保留，但从可用 Agent 列表移除。
- 从节点的“MCP 工具”直接添加并绑定连接，也可以在“我的 MCP”管理连接。新绑定按连接授权，无需先手动发现工具；运行时按需读取目录并加载相关工具。“查看工具”用于诊断，仅调用 MCP 的工具列表，不调用收费模型或执行任何业务工具。已有逐工具限制保留，明确转换并保存后才授权整个连接。凭据写入后不回显，留空保留，勾选清除才删除。平台托管连接可选入个人执行节点，连接地址和凭据仍不可编辑。未配置个人 MCP 域名白名单不会阻止使用平台工具。
- 普通用户能查看自己的 LLM 用量和 MCP 运行情况。管理员可以显式切换全站视图。PV / UV / 新增注册已移到 `/admin-stats.html`，对应 API 继续要求管理员。

本版模型由平台提供；模型目录不含 API 地址和密钥。用户自带模型的界面和凭据生命周期不在本版开放，后续可利用 API / Model 已添加的所有者字段扩展。

## 数据和运行边界

`V062__user_agent_workspace.sql` 为现有 Agent、Client、API、Model、Prompt、Advisor、MCP 表增加所有者；不复制账号、对话或知识库数据。既有配置归现有 `username=admin AND role=ADMIN` 账户，V062 先发布三条指定 Agent，随后 V063 发布全部符合条件的管理员原始 Agent 和指定的 11 个 MCP。找不到该管理员时使用不可访问哨兵，执行前必须确认该账户的实际 `user_id` 与启用状态，不能把未知归属改成公共。

个人 Agent 保存为一份经过白名单校验的配置 JSON，并在同一事务中生成可被原有执行引擎读取的 Client / Model / Prompt / Advisor / Flow 关系。更新采用版本校验，提交后失效装配缓存、移除旧图的运行 Bean；冲突返回 409，前端保留未保存输入。归档后禁止新调用。

节点编辑器使用 `workspace_config.schemaVersion=2` 的 `nodes` 数组，复用 V062 后的现有表，节点结构不需要新表；本次公共工具目录需再执行 V063，为 MCP 增加 `is_public` 开关。每个节点独享 Client、模型引用副本、Prompt 和 Advisor；平台 API 密钥仍只保存在平台 API 中。旧版扁平个人配置读取时转换为节点结构，只有显式保存才重建关系图。旧 API 的扁平保存请求仍可接收，工具只分配给可执行业务工具的节点。

模型副本 `capabilities_json.workspaceNode` 由服务端写入节点 ID、Client ID、所属 Agent 和工具授权上限。模型装配、实际工具调用以及动态恢复都限制到该节点；不能通过另一个节点的动态租约扩大权限。新节点的记忆 Advisor 不再自动传播到其他节点。Auto / Flow 的非执行角色不绑定业务 MCP，Flow 的能力分析读取执行器授权清单。节点编辑器按 MCP 连接绑定，具体工具由运行时按需匹配；已有逐工具授权保持原样，用户明确转换并保存后才扩大到整个连接。

Flow 执行节点具有两份独立指令：`taskPrompt` 附加在子任务执行的固定协议之后，`systemPrompt` 和输出要求用于最终整合。Auto 的质检协议、Flow 的计划 JSON、运行步骤格式占位符仍由服务端维护；界面不提供任意改写执行协议或自由连线。

当前单实例部署中，Agent 运行期间拒绝修改其执行图、归档或修改其使用的个人 MCP，提示等待运行结束；事务提交或回滚后都会释放编辑锁。这避免 Auto / Flow 执行到一半被替换配置。此锁不是跨实例协调机制，扩展为多实例前需要分布式运行/编辑租约或不可变版本图。

公共 Agent 分配时复制执行关系图，只保留已经公开的 MCP 绑定，私有文件/Git/运维/外部账号工具不复制；资源 ID 和连接归当前用户；同一用户多个公共 Agent 引用同一源 MCP 时复用该用户的连接。副本是使用时的快照，不自动同步后续源配置修改。原公共 Agent 下架、源 MCP 停用或撤回公开、平台源模型撤销或 API 停用后，下一次入口校验会阻止相应调用。已经向外部服务发送的请求不能撤回。

**公共工具仍使用平台的外部账号和配额。应用内连接隔离不等于外部账号隔离。** 管理员只应发布确实愿意共享的工具能力，原有人工审批规则仍适用。普通用户既不能读取平台令牌，也不能修改受保护公共副本来转发令牌。

调度入口、自动路由、装配、动态工具搜索、缓存命中和工具实际调用均校验用户归属。MCP 回调以 MCP ID 和工具名定位，避免不同连接同名工具互相覆盖。工具向量搜索限制到当前 Agent 可用的连接。公共 Agent 可以按需检索公共工具库；个人节点可用 `usePublicTools` 开关启用公共工具池，新建模板默认在执行节点启用，已有配置保持原值，可勾选后保存。具体连接显式勾选了部分工具时，该范围优先于公共工具池。

RAG 继续使用既有知识库；个人编辑器只能选择自己的知识标签。检索强制用户过滤，身份缺失或冲突不检索；父文档恢复也校验所有者。全局语义缓存等未经用户隔离确认的 Advisor 不出现在个人配置或公共副本中。

## 个人 MCP 策略

个人连接仅支持 HTTPS SSE / Streamable HTTP 和 Bearer 令牌。默认不开放任何域名；管理员通过以下配置开放可信服务的精确域名：

```yaml
agent:
  workspace:
    mcp-allowed-hosts: "mcp.example.org,tools.example.org"
```

不支持个人 STDIO / 服务器命令、内网地址、IP 段代理、URL 中的认证参数或任意请求头。创建及运行连接时均检查目标地址；SSE 消息端点必须保持同源。停用既有连接不依赖远端 DNS 正常。

白名单应由管理员控制并只包含可信域名；应用 DNS 校验不等于网络层出站隔离。部署环境仍应使用出站网络策略限制内网/云元数据访问。公共预置连接由管理员维护，可以使用原先的内网或 STDIO 配置。

每人最多保留 30 个未归档 Agent、添加 20 个个人 MCP；每个 Agent 最多选择 10 个 MCP。生成草稿每人 10 分钟最多 10 次，模型请求连接超时 10 秒、读取超时 90 秒且不自动重试。公共工具会增加每用户的会话或 STDIO 进程，当前没有连接池空闲回收策略；大量用户并发前需要单独压测和容量限制。

## 观测口径

- LLM：查询 ES 时强制按认证用户过滤；管理员选择全站后才移除此过滤。没有用户归属的系统历史日志仅全站可见。
- MCP：按用户和 MCP ID 记录调用、错误与延迟；健康检查仅探测被授权连接。页面展示当前进程启动以来的统计，重启后归零，不把累计值标成“最近 24 小时”。
- 网站统计：保留既有 GoAccess 日志采集和注册时间统计逻辑，仅移动页面与权限。

## 本地与生产迁移顺序

1. 停止旧应用，备份当前 MySQL。检查目标库已执行哪些迁移，确认已有 V061 结构，并核实 `username=admin AND role=ADMIN AND status=1` 账户的 `user_id` 是旧配置应归属的管理员。V062 会统一设置七张配置表的现有记录所有者，不要在未确认归属时执行或启动新版本。
2. 仅对尚未执行 V062 的目标 MySQL 数据库**执行一次** V062。V062/V063 均包含非幂等 DDL，不具备整体事务回滚能力；字段或索引已存在、部分失败时，应核对结构与数据后逐项处理，不能直接重跑整文件。
3. 核对所有待公开的管理员原始 Agent，以及 V063 中 11 个 MCP ID 在目标库对应的实际服务与共享范围，再对尚未执行 V063 的库执行一次 V063。它会公开符合条件的管理员原始 Agent 和指定 MCP，并开放公共 Agent 所用模型。迁移完成后使用新 JAR 和匹配静态资源启动；先验证管理员原有 Agent，再用两个测试账户验证公共 Agent、创建/更新、工具与观测隔离。
4. 新用户登录后即可选择公共 Agent，也可以创建自己的 Agent；不会直接调用管理员的原始 Agent ID。个人 MCP 需先配置可信域名，公共 MCP 不需要用户配置密钥或白名单。
5. 检查平台公开模型目录与预期一致。V062 先开放三条指定公共 Agent 所用模型，V063 扩展到全部符合条件的公共 Agent 所用模型。更换模型提供策略时通过管理员模型配置或审核后的数据库变更管理。已完整执行 V062/V063 的数据库无需重复迁移，也没有本次专用的 PostgreSQL 迁移。

迁移与 CRUD 的自动验证在独立本地测试库完成，不替代目标环境验收。原 JAR 不能在多用户已开放的状态下直接回滚使用：旧版本缺少这些归属校验。回滚应暂停对外访问并恢复成对的数据库备份和应用版本。

### V062 后的启动与初始化排查

若启动时出现 `org.postgresql.util.PSQLException: relation "ai_client_model" does not exist`，是 MySQL 业务查询使用了 PostgreSQL 连接，不应在 PostgreSQL 补建此表。`DataSourceConfig` 显式提供默认的 `mysqlJdbcTemplate`（别名 `jdbcTemplate`），业务查询指定该模板；向量查询继续指定 `pgVectorJdbcTemplate`。更新代码并重新编译后重启应用。

若 V062 的字段已存在，但旧配置的 `owner_user_id` 仍为 `__legacy_unowned__`、三个公共 Agent 的 `is_public` 仍为 0，说明数据初始化尚未生效。停止应用、备份 MySQL，在目标库的同一连接中完整执行 `docs/dev-ops/repair-v062-workspace-data.sql`。它只补数据、不重复建字段，并保留已明确归属的个人配置；没有启用的 `admin` 管理员账户时不改数据。检查脚本末尾输出的归属、公开标记及可用模型数量后再启动。不要重复执行整份 V062 的 DDL。

`ai-agent-station-study-app/src/test/frontend/workspace-ui.integration.cjs` 在真实 Chromium 中运行页面、使用确定性 API 数据，覆盖创建/更新、冲突保留输入、MCP 令牌保留/替换/清除、草稿审核、观测权限和手机布局。它不替代后端授权测试。

这些验证不调用真实收费模型或远端 MCP，也不等于生产并发压测；上线前仍需在测试账户完成一次真实 Fixed / Auto / Flow、MCP 和生成草稿联调。

## 管理员旧配置入口的兼容

旧管理员 CRUD 和画布创建配置时，同样使用当前已认证管理员作为所有者，忽略请求中伪造的 owner / 审计人。画布拒绝引用其他账户的 Client / Model / Prompt / Advisor / MCP。模型管理 API 增加 `platformEnabled`：新建默认 0，只有显式置为 1 才出现在普通用户的平台模型目录。

旧管理员编辑/删除接口仍是维护入口，变更其配置前应先暂停相关运行；个人工作区才具有上述运行/编辑互斥保护。修改平台密钥或 API 地址后需重启应用重建辅助模型池。停用模型或 API 则会在后续模型池调用时重新检查，无须等待旧缓存过期。

## 公共工具目录与检索修复（V063）

V063 指定 11 个通用连接 ID：`5005`、`5006`、`9003`、`9004`、`9005`、`9007`、`9009`、`9012`、`9013`、`9016`、`9017`，仅公开其中归属管理员、已启用且不是副本的连接。本地对应高德地图、百度搜索、天气、食谱、营养查询、计算器、arXiv、翻译、语法检查、12306、千帆联网搜索；其他环境执行前应核实 ID 与服务的对应关系。文件、Git/GitHub、运维、公众号、日历/待办、Strava、文档转换等保持私有。设置源 MCP 的 `is_public=0` 可撤回共享；其副本无法继续发现或调用。设置源 Agent 的 `is_public=0` 可下架该 Agent。

公共目录的向量依然以源 MCP ID 存储，检索时只查询当前用户获授权的源目录，再映射为本人的连接 ID 进行实际调用，避免用户副本 ID 没有向量而检索为空。向量缺失或不可用时，可在获授权的工具目录内按名称/描述匹配；不会扩大到私人目录。没有可匹配条目或服务连接失败仍会返回不可用，不编造调用结果。Flow 工具分析阶段按执行器权限发现工具，自身仍不能执行业务工具。

个人节点的公共工具池在保存时记录当时已分配的公开连接，增加新公共连接后可重新保存以纳入；停用与撤销实时按数据库校验。公共副本继续使用创建时的配置快照，源连接凭据后续修改不会自动复制。

本次验证：52 项测试通过（包含 16 项真实 MySQL 隔离库测试）；浏览器覆盖平台连接无白名单使用、发现失败后重试、节点工具选择与公共池开关、撤销状态、凭据隐藏和 320–1440px 布局。JAR 打包成功。外部 11 个 MCP 服务未逐一做实时连通性验证。

## MCP 连接绑定与节点补充信息共享（2026-10-08）

个人节点新增或转换后的绑定保存为 `{mcpId, allTools:true, toolNames:[], loadMode:"ON_DEMAND"}`。绑定授权整个 MCP，包括该服务未来新增的工具。装配时不连接这些 MCP，也不预先把其全部 schema 交给模型；`request_tool` 或执行器的动态能力解析根据当前任务需求加载相关工具。显式绑定优先，公共池补充，并保持每条需求和每次请求的数量上限。新的个人连接没有持久化工具目录时，会在首次运行需求解析时读取工具清单并按名称/描述匹配，用户无需先手动发现。界面的“查看工具”只用于诊断。

底层 `model -> tool_mcp` 关系仍保留，用于权限、删除保护、运行锁和配置失效。已有逐工具限制不自动扩大；编辑器提供明确的“改为按连接绑定”操作。已有整连接绑定在重新保存后转为按需加载。已执行 V062/V063 的数据库不需要新增 SQL。

对话选择器默认展示 Agent 名称；同名条目用模式和序号区分。MCP 观测按当前可见连接批量读取名称，内部 ID 位于可展开详情，搜索支持名称和 ID。健康列表仅包括当前进程已建立的连接，所以刚绑定、尚未使用的 MCP 暂时没有运行快照；工具统计在实际调用后产生。

`ask_user` 的已提交回答连同问题、所属节点和用户身份保存到现有运行事件及快照。`RunUserInputAdvisor` 在 Fixed / Auto / Flow 后续节点的模型请求中加入同一用户、同一次任务的补充，提示复用已有答案，只追问缺失或冲突信息。不把回答升为系统指令，不改变工具权限。超时、空答案不参与共享；同一运行恢复可以读取快照，另一用户或新任务不能继承。已经开始的并行模型请求无法追溯接收稍后才提交的回答，之后启动的请求会读取最新补充。

### Flow 能力目录与确认计划后的事件回放

Flow 的分析、规划节点从执行器读取 MCP 授权；编辑器展示只读继承列表和公共池设置，可跳转到执行器修改。运行时的完整绑定目录与已加载回调分开：分析开始时，即使没有能力需求或尚未加载任何回调，也可读取已授权 MCP 的工具名称、描述、参数摘要。优先读取已保存的目录；新连接尚无目录时只做 `tools/list` 发现，不执行业务工具。保存目录不能证明服务当前连通；读取失败标为“能力未知”，不推断“没有能力”。目录有数量/长度限制并明确报告省略，避免把工具加载数量上限误当成所有可用能力的范围。

规划和子任务执行也能读取该目录。实际调用仍先 `request_tool` 按需加载，精确工具名优先匹配授权目录；分析/规划阶段只有发现权限。`request_tool` 给模型的回复附带有长度限制的能力与参数摘要，前端卡片的工具名称格式不变。不会把整个目录变成当前模型可执行的 tools schema。

确认计划接口会重放已有运行事件。前端现在按账户、会话、运行和事件 ID 去重；待确认计划的本地保存/恢复同时保存去重记录。计划卡原位更新；并行同名工具按 `callId` 匹配开始/结束。新的同名工具调用具有不同事件 ID，仍正常显示。兼容没有事件 ID 的历史流时不按文本去重，以免误删真实调用。
