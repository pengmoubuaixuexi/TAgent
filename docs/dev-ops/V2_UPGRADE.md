# TAgent v2.0.0 升级指南

v2.0.0 在个人 Agent 工作区上增加个人模型连接、版本管理、知识入库、持久运行历史、产物和用量账本。版本号对应本次功能里程碑；上线效果仍取决于部署配置和外部模型、MCP 服务。

## 功能与配置入口

| 入口 | 能力 | 说明 |
| --- | --- | --- |
| 我的 Agent | Fixed / Auto / Flow 节点配置、草稿、版本对比与启用、节点调试 | 调试仍受本人权限、预算和工具限制；版本回退先生成草稿再显式启用 |
| 模型连接 | 自带 OpenAI 兼容 API、密钥轮换与撤销 | [加密主密钥、域名白名单和辅助模型授权](MODEL_CONNECTIONS.md) |
| 我的知识库 | 异步入库、阶段进度、失败重试、片段预览与检索测试 | [知识库入库与维护](KNOWLEDGE_INGESTION.md) |
| 运行历史 | 本人运行状态、回答、依赖步骤与有限诊断回放 | [历史保留和中断恢复边界](RUN_HISTORY.md) |
| 产物与反馈 | Markdown、CSV 表格、单个代码文件，编辑修订、下载与显式复用 | 通过内置 `create_artifact` 保存；代码只保存，不自动执行；不提供 PDF、Word 或 XLSX 生成 |
| 我的用量 | 平台额度、并发准入、每次模型调用预留与结算 | [持久用量账本](MODEL_USAGE.md)；价格未知时不展示为零费用 |
| EvalOps | 规则分、不同模型 Judge、失败题补评、逐题对照 | [评测说明](EVAL_OPS.md)；用户反馈可选转为数据集草稿，需人工发布 |

统一导航和收件箱覆盖工作台、运行与观测页面。任务完成或失败会通知本人；当前可见任务可自动标为已读，也可在收件箱使用“全部已读”。通知不是计划或工具审批。

FLOW 分析和规划读取执行节点的授权能力目录，执行阶段再按需装配具体工具。`ask_user` 的有效回答供同一用户、同一运行的后续节点读取；不会赋予额外工具权限。大工具结果保留原文证据并向模型返回有界摘要及引用，避免上下文被重复长结果占满。

## 从已应用 V063 的环境升级

1. 安排维护窗口，暂停新任务和 Agent 配置修改，等待活动任务结束。对现有 MySQL、PostgreSQL、Elasticsearch、应用私有数据卷、配置和旧镜像做一致备份。保留旧 JAR；已有加密模型凭据时单独保管原主密钥。
2. 核对实际数据库结构和迁移记录，按顺序仅执行尚未应用的 V064–V069。首次部署先完成基础库及先前迁移。不要重复导入开发库，不要重跑 V062/V063 来修补 v2 结构。
3. 保留服务器自己的数据库、模型、MCP、域名和代理配置；不要用开发机的配置文件覆盖。设置固定的 `MODEL_SECRET_MASTER_KEY`，并为个人模型与个人 MCP 分别配置受信域名。
4. 构建并上传新应用，使用 `server/Dockerfile` 的多阶段方案移除 JAR 内的私有配置。核验最终镜像，再仅重建应用容器，保留数据库与私有数据卷。
5. 按下方验收项检查新进程。上线前原有失败任务不会自动重跑；旧进程中断的任务应由用户查看历史后决定是否重新执行。

| 迁移 | 新增内容 |
| --- | --- |
| V064 | 个人模型加密凭据、辅助模型授权策略、API 密钥引用列 |
| V065 | Agent 草稿与版本；符合条件的原有配置回填为当前版本 |
| V066 | 知识库入库任务、工作租约与状态 |
| V067 | 持久运行历史与诊断 |
| V068 | 用户额度、每日用量、运行和请求级账本 |
| V069 | 产物、修订和用户反馈 |

脚本位于 [sql-migrations](sql-migrations/)。V065、V069 包含非幂等 DDL；MySQL DDL 隐式提交，失败后先核对已提交结构，不能认为整份脚本已回滚。V065 只回填符合条件 Agent 的当前配置，不恢复过去版本；迁移后到新应用接管前应暂停 Agent 配置变更。

`MODEL_SECRET_MASTER_KEY` 是 32 字节随机值的 Base64 编码，只生成一次并私密备份。空配置允许平台模型继续工作，但禁用个人密钥保存和使用。改变或丢失主密钥后，数据库中的旧密文无法直接解密。当前支持提供商 API Key 轮换，不提供自动加密主密钥轮换。

`server/v2_ops.py` 的迁移、备份及恢复命令只支持指定的本机隔离测试库，**不能作为生产迁移脚本**。详见 [本地运维演练](V2_LOCAL_OPERATIONS.md) 和 [服务器部署说明](server/README.md)。

## 配置与验收

- 登录、退出、注册、修改密码和 CSRF 正常；普通用户无法读取其他用户的会话、模型凭据、知识库、运行和产物。
- 用本人模型完成一次请求；关闭平台辅助服务后，需使用辅助模型的操作明确拒绝，不借用其他用户的密钥。
- Fixed、Auto、Flow 分别验证执行、取消、刷新重连；FLOW 的依赖标签、计划确认和 `ask_user` 回答保持正确，工具卡片不重复。
- 验证 MCP 连接、动态工具发现、已知业务查询和取消后的行为；按实际服务测量容量。连接池空闲回收不等于已经验证大规模并发。
- 上传资料后核对入库进度与检索；失败可显式重试，删除后不可再召回。原件目录必须挂载到持久私有卷。
- 请求生成 Markdown、表格或代码产物，核对下载内容、修订及访问权限；运行历史和通知能跳转到对应任务。
- 用不同模型执行 Judge，检查逐题评分和失败补评。执行 `PASS` 仅表示任务完成，不能代替答案质量验收。
- 正式域名、证书、Secure Cookie、SSE 代理、取消及重连需在目标环境单独验证。不要把本地编译、模拟测试或示例证书验证当作线上验收。

每日平台额度默认每用户 500,000 Token、200 次请求、3 个并发运行；单任务预算与单次上下文上限是独立配置，修改日额度不会同时修改它们。详见用量说明及代码配置默认值。

当前知识库仅限制单文件大小，尚无每用户累计存储量、文件数和排队任务配额。应监控私有卷容量并限制上传入口；不宜将当前版本描述成可无限量开放上传。单实例运行锁和本地原件存储也不代表多实例部署已经验证。

## 回退与验证工具

切换新应用前保留旧镜像和配置；新版本产生数据后，回退要同时考虑结构、账本、原件、索引及密钥，不能仅替换旧 JAR 或只恢复 MySQL。先停止写入，确认恢复点，再在隔离环境演练。

标准编译检查：

```bash
mvn -pl ai-agent-station-study-trigger -am clean test-compile
```

完整本地验证入口为 `docs/dev-ops/verify_v2_local.ps1`，只接受脚本指定的隔离 MySQL 与 Redis。脚本默认离线 Maven 构建，需要提前准备依赖缓存；浏览器套件需要安装 Playwright，并通过 `CHROME_PATH` 指定可用 Chromium/Chrome（Windows 默认路径见各套件）。真实隔离存储、HTTPS 模板和恢复检查有独立前提，不要连接生产数据库运行测试。
