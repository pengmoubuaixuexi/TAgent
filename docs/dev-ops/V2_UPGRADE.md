# TAgent v2 升级指南

v2.0.0 在个人 Agent 工作区上增加个人模型连接、版本管理、知识入库、持久运行历史、产物和用量账本。版本号对应本次功能里程碑；上线效果仍取决于部署配置和外部模型、MCP 服务。

## 功能与配置入口

| 入口 | 能力 | 说明 |
| --- | --- | --- |
| 我的 Agent | Fixed / Auto / Flow 节点配置、草稿、版本对比与启用、节点调试 | 调试仍受本人权限、预算和工具限制；版本回退先生成草稿再显式启用 |
| 模型连接 | 自带 OpenAI 兼容 API、密钥轮换与撤销 | [加密主密钥、域名白名单和辅助模型授权](MODEL_CONNECTIONS.md) |
| 我的知识库 | 异步入库、阶段进度、失败重试、片段预览与检索测试 | [知识库入库与维护](KNOWLEDGE_INGESTION.md) |
| 运行历史 | 本人运行状态、回答、依赖步骤与有限诊断回放 | [历史保留和中断恢复边界](RUN_HISTORY.md) |
| 产物与反馈 | Markdown、CSV 表格、单个代码文件，编辑修订、下载与显式复用 | 通过内置 `create_artifact` 保存；代码只保存，不自动执行；不提供 PDF、Word 或 XLSX 生成 |
| 我的用量 | 平台额度、并发准入、每次模型调用预留与结算 | [持久用量账本](MODEL_USAGE.md)；价格未知时不展示为零费用 |
| EvalOps | 规则分、不同模型 Judge、失败题补评、逐题对照 | [评测说明](EVAL_OPS.md)；用户反馈可选转为数据集草稿，需人工发布 |

统一导航和收件箱覆盖工作台、运行与观测页面。任务完成或失败会通知本人；当前可见任务可自动标为已读，也可在收件箱使用“全部已读”。通知不是计划或工具审批。

FLOW 分析和规划读取执行节点的授权能力目录，执行阶段再按需装配具体工具。`ask_user` 的有效回答供同一用户、同一运行的后续节点读取；不会赋予额外工具权限。大工具结果保留原文证据并向模型返回有界摘要及引用，避免上下文被重复长结果占满。

## 从已应用 V063 的环境升级

1. 安排维护窗口，暂停新任务和 Agent 配置修改，等待活动任务结束。对现有 MySQL、PostgreSQL、Elasticsearch、应用私有数据卷、配置和旧镜像做一致备份。保留旧 JAR；已有加密模型凭据时单独保管原主密钥。
2. 核对实际数据库结构和迁移记录，按顺序仅执行尚未应用的 V064–V069。首次部署先完成基础库及先前迁移。不要重复导入开发库，不要重跑 V062/V063 来修补 v2 结构。
3. 保留服务器自己的数据库、模型、MCP、域名和代理配置；不要用开发机的配置文件覆盖。设置固定的 `MODEL_SECRET_MASTER_KEY`，并为个人模型与个人 MCP 分别配置受信域名。
4. 构建并上传新应用，使用 `server/Dockerfile` 的多阶段方案移除 JAR 内的私有配置。核验最终镜像，再仅重建应用容器，保留数据库与私有数据卷。
5. 按下方验收项检查新进程。上线前原有失败任务不会自动重跑；旧进程中断的任务应由用户查看历史后决定是否重新执行。

| 迁移 | 新增内容 |
| --- | --- |
| V064 | 个人模型加密凭据、辅助模型授权策略、API 密钥引用列 |
| V065 | Agent 草稿与版本；符合条件的原有配置回填为当前版本 |
| V066 | 知识库入库任务、工作租约与状态 |
| V067 | 持久运行历史与诊断 |
| V068 | 用户额度、每日用量、运行和请求级账本 |
| V069 | 产物、修订和用户反馈 |

脚本位于 [sql-migrations](sql-migrations/)。V065、V069 包含非幂等 DDL；MySQL DDL 隐式提交，失败后先核对已提交结构，不能认为整份脚本已回滚。V065 只回填符合条件 Agent 的当前配置，不恢复过去版本；迁移后到新应用接管前应暂停 Agent 配置变更。

`MODEL_SECRET_MASTER_KEY` 是 32 字节随机值的 Base64 编码，只生成一次并私密备份。空配置允许平台模型继续工作，但禁用个人密钥保存和使用。改变或丢失主密钥后，数据库中的旧密文无法直接解密。当前支持提供商 API Key 轮换，不提供自动加密主密钥轮换。

`server/v2_ops.py` 的迁移、备份及恢复命令只支持指定的本机隔离测试库，**不能作为生产迁移脚本**。详见 [本地运维演练](V2_LOCAL_OPERATIONS.md) 和 [服务器部署说明](server/README.md)。

## 配置与验收

- 登录、退出、注册、修改密码和 CSRF 正常；普通用户无法读取其他用户的会话、模型凭据、知识库、运行和产物。
- 用本人模型完成一次请求；关闭平台辅助服务后，需使用辅助模型的操作明确拒绝，不借用其他用户的密钥。
- Fixed、Auto、Flow 分别验证执行、取消、刷新重连；FLOW 的依赖标签、计划确认和 `ask_user` 回答保持正确，工具卡片不重复。
- 验证 MCP 连接、动态工具发现、已知业务查询和取消后的行为；按实际服务测量容量。连接池空闲回收不等于已经验证大规模并发。
- 上传资料后核对入库进度与检索；失败可显式重试，删除后不可再召回。原件目录必须挂载到持久私有卷。
- 请求生成 Markdown、表格或代码产物，核对下载内容、修订及访问权限；运行历史和通知能跳转到对应任务。
- 用不同模型执行 Judge，检查逐题评分和失败补评。执行 `PASS` 仅表示任务完成，不能代替答案质量验收。
- 正式域名、证书、Secure Cookie、SSE 代理、取消及重连需在目标环境单独验证。不要把本地编译、模拟测试或示例证书验证当作线上验收。

每日平台额度默认每用户 500,000 Token、200 次请求、3 个并发运行；单任务预算与单次上下文上限是独立配置，修改日额度不会同时修改它们。详见用量说明及代码配置默认值。

当前知识库仅限制单文件大小，尚无每用户累计存储量、文件数和排队任务配额。应监控私有卷容量并限制上传入口；不宜将当前版本描述成可无限量开放上传。单实例运行锁和本地原件存储也不代表多实例部署已经验证。

## 回退与验证工具

切换新应用前保留旧镜像和配置；新版本产生数据后，回退要同时考虑结构、账本、原件、索引及密钥，不能仅替换旧 JAR 或只恢复 MySQL。先停止写入，确认恢复点，再在隔离环境演练。

标准编译检查：

```bash
mvn -pl ai-agent-station-study-trigger -am clean test-compile
```

完整本地验证入口为 `docs/dev-ops/verify_v2_local.ps1`，只接受脚本指定的隔离 MySQL 与 Redis。脚本默认离线 Maven 构建，需要提前准备依赖缓存；浏览器套件需要安装 Playwright，并通过 `CHROME_PATH` 指定可用 Chromium/Chrome（Windows 默认路径见各套件）。真实隔离存储、HTTPS 模板和恢复检查有独立前提，不要连接生产数据库运行测试。

## v2.1.0 升级

v2.1.0 加快知识库入库，支持失败后续做，并增加按用户的知识库配额。只需在 v2.0.0（已完成 V064–V069）的基础上执行一个迁移：

1. 备份 MySQL。
2. 执行 [V070](sql-migrations/V070__knowledge_ingestion_resume_and_quota.sql)：`ai_rag_ingestion_task` 新增 `resume_fingerprint`、`retry_day`、`retry_day_count`，`ai_client_rag_order.rag_name` 放宽到 255。只执行一次。
3. 再启动新版本。顺序不能反：新版本查询入库任务时依赖新增列。

新增配置均有默认值，可不修改现有配置：

| 配置 | 默认值 | 说明 |
|---|---|---|
| `agent.rag.enrichment.mode` | `llm` | `llm`：每个父块一次模型调用生成标题和子块上下文；`rule`：不调模型，只用文件名和 Markdown 标题 |
| `agent.rag.enrichment.concurrency` | `4` | 同时处理的父块数 |
| `agent.rag.ingestion.max-model-calls` / `max-seconds` / `max-tokens` | `1000` / `1800` / `3000000` | 入库独立预算，不占用对话任务预算 |
| `agent.rag.quota.enabled` | `true` | 普通用户配额开关，管理员不受限 |
| `agent.rag.quota.max-files` / `max-total-mb` | `50` / `200` | 每人文件数与总容量 |
| `agent.rag.quota.daily-ingestions` | `20` | 每天新提交与重试次数之和，北京时间零点重置 |
| `agent.rag.quota.max-pending` | `3` | 同时排队或处理中的文件数 |
| `agent.rag.quota.max-parents-per-file` | `300` | 单个文件切分后的父块上限 |

注意：

- 标题与上下文仍分别受 `agent.rag.parent-title.enabled` 和 `agent.rag.contextual-retrieval.enabled` 控制，这两项必须位于 `agent.rag.*` 下。
- V070 之前失败的入库任务没有续做记录，第一次重试会整份重新处理。
- 若入库增强模型返回 4xx（例如模型名不存在），同一文件的其余段落不再请求模型，文件照常入库，任务显示未生成上下文的段落数；修复模型后重试失败任务即可重新生成。

## v2.2.0 升级

本次包含模型故障切换、统一附件、Python 沙箱、持久运行轨迹与改进验证。原先四批开发计划合并发布为 v2.2.0。

1. 先停止应用写入，备份 MySQL、原有文件/索引/向量存储、旧镜像、配置和固定的 `MODEL_SECRET_MASTER_KEY`。保留同一恢复点；不要升级时重新生成主密钥。
2. 确认 V070 已完成，按顺序仅执行缺失的迁移：

   | 迁移 | 变更 |
   |---|---|
   | [V071](sql-migrations/V071__model_catalog_and_health.sql) | 模型清单和健康表，规范已有档位并初始化候选；核对平台发布范围和个人模型归属 |
   | [V072](sql-migrations/V072__chat_files_and_artifact_provenance.sql) | 附件及运行关联表，产物修订来源字段与索引 |
   | [V073](sql-migrations/V073__run_trace.sql) | 运行轨迹及大字段存储表 |
   | [V074](sql-migrations/V074__improvement_suggestions.sql) | 改进建议、候选草稿与对比评测关联 |
   | [V075](sql-migrations/V075__usage_day_carried_tokens.sql) | 日用量账本新增 `carried_tokens` |

   DDL 不保证整份幂等；部分执行失败后先检查表、列与索引，不要盲目重跑。线上已完成迁移的实例应跳过。
3. 合并配置示例中的 `agent.attachments`、`agent.sandbox`、`agent.trace` 和 `agent.model-failover`；保留本实例额度、密钥、域名及存储设置。使用请求层重试后将 `resilience4j.retry.instances.llmCall.max-attempts` 设为 `1`，避免重复叠加。
4. 沙箱启用步骤见 [部署说明](../../sandbox-runner/README.md)。构建两个镜像并设置共享令牌；应用 `.env` 设置 `TAGENT_SANDBOX_ENABLED=true`。执行镜像是 build-only 服务，不要把它作为常驻服务启动。
5. 启动后核对登录/普通用户权限、附件上传解析与读取、产物执行与下载、真实模型响应及历史轨迹；确认 Prometheus 抓取、Grafana 告警规则。只通过编译不代表外部模型和目标服务器已验收。

新配置与边界：

- 附件 `storage=auto`：配置 OSS 时使用 OSS，否则使用持久应用数据目录。单文件默认 50 MiB，每条消息最多 10 个；总原文容量默认 10 GiB，超过时按最后使用时间清理。不要承诺附件永久保留。
- 轨迹默认启用且 `retention-days=0` 表示长期保留。可设置保留天数；有反馈、评测或改进引用的轨迹保留。新模板停写旧 `ai_event_log`，不自动删旧数据。
- `agent.run-budget.overrun-ratio=0.2` 允许阶段收尾，达到硬边界后停止；平台日额度超出部分记录到次日账本。它不增加配置的日额度或单任务目标额度。
- `agent.context.default-output-limit=25600` 是未指定输出上限时的默认值，并不证明所有模型支持该长度；按实际服务商调整。
- 模型候选只在相同归属内选择，需正确登记模型能力与档位；改进建议必须有完整有效的对比评测并由用户确认，不能当作自动发布。
- 新版已经写入后，回退需评估数据库、产物和用量数据的兼容性；不能仅换旧 JAR 就假定恢复成功。


## v2.2.1 升级

本次是 v2.2.0 的兼容修复版本，没有新增数据库迁移。保留现有数据库、密钥、私有配置和持久数据卷；无需重建沙箱 runner 或执行镜像。

- 构建并部署新应用 JAR，核对 JAR 包含 `/static/vendor/tailwind-3.4.17.min.js` 与许可证。使用已有部署流程剔除私有配置，不要以仓库示例覆盖服务器配置。
- 个人模型默认精确允许 `api.openai.com`、`api.deepseek.com`、`api.siliconflow.cn`、`api.xiaomimimo.com`；可以通过 `PERSONAL_MODEL_ALLOWED_HOSTS` 或显式属性覆盖。已有配置文件若覆盖该属性，需要由部署者更新自己的精确列表。HTTPS、公共 DNS、同源与用户授权检查继续生效。
- 公共 MySQL 示例将 JDBC 时区参数调整为 `connectionTimeZone=SERVER`。升级前核对数据库服务器、会话和历史时间的实际语义；这不是 SQL 迁移，也不要批量改写已有时间数据。
- 回归核对：按来源文件回答的 RAG 问题、Fixed 引导、Flow 指定步骤重做、个人模型保存后的立即检查、证据图生成与缓存、改进对比评测。证据图的“尚未核验”表示没有可用核验结果，不等于已证明没有依据。
- URL 图片响应体有整体时限；外部 MCP 不可用仍可能导致任务无法完成。固定 WMO 释义和 POI 校验用于约束证据，不保证每次生成回答都正确。

保留旧应用与配置备份作为回退点；此版本不要求恢复或重建数据库。
