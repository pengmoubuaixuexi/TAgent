# Security Policy

## Reporting a Vulnerability

Please do not open public issues for sensitive security problems.

Use GitHub private vulnerability reporting if available, or contact the repository owner through GitHub with a minimal description of the affected area. Avoid sharing real secrets, production data, or private logs in public comments.

## Public Repository Hygiene

This repository should not contain:

- API keys, access tokens, cookies, private keys, or service account files.
- Database backups, production data, runtime logs, or trace exports.
- Personal documents, chat histories, temporary debugging files, or local browser state.

If you find sensitive material in the repository history, report it privately so it can be rotated and removed properly.
